# Brain Bootloader — 思维预检

> **读法**：括号里是白话。**按白话执行**。易误读以各节说明及 `references/` 对照表为准。

## 定位

动手前的轻量检查：确认「是不是在解决正确的问题」。  
不是完整设计流程；简单任务直接跳过。

## 触发条件

- 用户提出方案/工具/框架，要求按此执行
- 多变量、不确定、失败成本高
- 「帮我做 X，用 Y 方法」
- 两难权衡、怕只听一面就拍板
- 感觉方向不对，但说不清

**跳过**：路径清晰、无争议的小操作。

## 五步预检

每步能一句就一句。

### 1. 目标重定义

做法 ≠ 目标。先剥掉「用什么做」，问「最后要什么结果」。

```
用户说：帮我用 React 重写这个页面
真实目标可能是：性能 / 维护成本 / 旧代码改不动
```

### 2. 隐藏假设扫描

- 这个方案一定最合适吗？
- 有没有「大家都这么做」所以默认正确？
- 有没有因为不知道替代品，路径被锁死？

### 3. 信息差补充

补上用户可能不知道、但会影响决策的信息；会变的事实先核实。

### 4. 替代方案速览

| 类型 | 问题 |
|------|------|
| 更简单 | 用两成复杂度，能不能覆盖八成效果？ |
| 更稳 | 有没有更成熟、更少踩坑的路？ |
| 更优 | 有没有上限更高的路线？ |

原方案最好就保留，但要说依据。

### 5. 对抗性复核

如果会失败，最可能死在哪？有没有致命盲区？

## 条件模块（按需加载，别每次全读）

| 信号 | 动作 |
|------|------|
| 两难 / 只给一个结论 / 要判断趋势 | `read` 本目录 `references/dialectics.md`（叩两端 · 临界 · 时中） |
| 谈判、多方博弈、激励设计 | `read` `references/engagement.md` 的策略红线 |
| 对方要的是「学会」不是「只要答案」 | `read` `references/engagement.md` 的教学旁注 |

**高频易误读（主路径够用就停）：**

- **两端** = 当前真对立轴 A↔B，不是固定「极限成功 vs 极限失败」
- **时中** = 现在最合适（可写改偏条件），不是永远站中间
- **启而不发** = 点一下留空间；对方要步骤清单时直接给，别卖关子

无上述信号 → 做完五步即可，不必打开 references。

## 追问规则

- 事实先自己查，不问用户
- 决策给 2–3 个选项，每个附一条「选这个最可能栽哪」
- 一次只问一个；靶心是「该不该做」

五步都清晰就跳过追问，直接结论。

## 输出格式

```
方向判断：✅ 可行 / ⚠️ 调整 / ❌ 换方案
张力轴与两端：[若适用——先写 A↔B，再各推到头一行]
临界与时中：[反转信号 + 当下偏哪边、何种信号改偏]
建议路线：[一句话]
关键风险 / 红线：[如有]
下一步：brainstorming / 直接执行
```

对外优先白话（轴、两边、翻面条件、现在偏哪）；典源词可作标签。
