# 沙箱与升权（每条 bash 命令都在沙箱里跑）

你的 bash 命令跑在 **Landlock 文件系统沙箱**里，默认策略是：

- **全系统只读**，只有这些地方能写：当前工作目录（cwd）、`/tmp`、`/dev/null`
- 内存上限默认 **1 GiB**（进程树匿名内存，超了 SIGKILL 整组，退出码 137）
- 网络**不拦**（访问网络不影响）

## 撞墙了长什么样

写工作区之外的地方会被内核拒掉，报错通常是：

```
bash: 行 1: /etc/xxx: 权限不够
bash: /usr/local/bin/xxx: 只读文件系统
```

**这不是普通权限问题，`sudo` 也解决不了** —— 是沙箱在挡。同理，`sandbox-shell: 命令进程树匿名内存超出上限`
是内存墙，不是机器真的没内存。

看到这类报错时：先判断这件事是不是任务真的需要。需要就走下面的申请，**不要反复重试同一条命令**
（同一条被拒的命令重试一百次也还是被拒），也不要改用变量拼接、命令替换之类的写法去绕过——绕过不是通过。

## 怎么申请

用 **`sandbox-allow`** 工具，它是唯一的一次性升权入口：

```
sandbox-allow({
  command: "完整的那条命令",          // 获批后要跑的就是它
  permission: "write-paths",          // 优先这个；只在没法限定目录时才 full-access
  paths: ["/home/clyzhi/disk/xxx"],   // 最小可写目录，由你声明
  justification: "一句话说明为什么要写这里",  // 用户看这句决定批不批
})
```

几条要紧的：

- **`paths` 是你自己列的目录**，工具不会从 command 里拆。目录要已存在；不存在时申请上一级再 `mkdir`，
  但那一级只为补这一层，别拿去写别的东西
- **路径里出现 `/`（含 `/.`、`/..`）整次拒绝** —— 那等于要全盘
- **`full-access` 只留到最后**：它完全取消文件系统沙箱。能指名一个目录就别用它
- 命令引用敏感路径（`.env`、`~/.ssh` 这类）不会被硬拒，会转成人工审批并在窗口里标出命中的那一段。
  正当需要就照常申请
- **需要更多内存**（重型构建 / 测试）时给 `memoryMb`，必须写**具体数字**（例：`2048`）。
  默认 1 GiB 不是摆设，多个测试文件合跑经常就栽在这
- 申请会弹窗给用户批。审批通过只对**这一条命令**生效，不会给你持续权限

## 什么不用申请

- 写工作区、`/tmp`、`/dev/null`：沙箱本来就允许
- 只读操作（看文件、git status、跑测试）：只读不受限
- 已经在长期/本 session 信任根里的目录：会自动放行（审批窗里能看见哪些命中）

## 一条硬规矩

**不要为了绕过沙箱而改造命令。** 比如把要写的文件挪到 `/tmp` 再 `mv` 过去、用
`python -c` 包一层、或者拼一个看起来人畜无害的路径——这些手法要么被同样拒掉，
要么就是在躲审批窗。需要写哪儿就申请哪儿。
