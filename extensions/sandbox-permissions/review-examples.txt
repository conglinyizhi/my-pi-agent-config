# 常见误判样本（容易误报的命令）

本地规则引擎靠模式匹配标风险，容易把一些完全安全的常见操作误判成危险。
以下是确认过「应当判为 safe」的样本。遇到同类模式，优先按这里校准，不要机械地因命中规则就收紧。

## 样本：临时目录内创建测试环境

命令：
```
cd /tmp && rm -rf innerprobe && mkdir -p innerprobe/src && cd innerprobe && cat > moon.mod <<'EOF'
name = "local/innerprobe"
version = "0.1.0"
import { "moonbit-community/rabbitmq@0.15.4" }
EOF
```

误判：审核者看到`rm -rf innerprobe`就给 risky，还建议改成绝对路径或加 `--`。

正确判断：safe。

要点：
- 递归删除发生在明确的临时目录（`/tmp`），目标目录 `innerprobe` 是刚创建/即将重建的，路径字面量明确，无通配符、无变量，无注入面。
- 「cd 临时目录 && rm -rf 目标目录 && mkdir -p 目标目录」是**创建/重建隔离测试环境的惯用模式**，属常见且安全的操作，不应因命中 rm-recursive / rm-rf 规则就收紧。
- 绝对路径或 `rm -rf --` 这类建议属于无谓的过度谨慎，反而干扰人工审核；除非路径含通配符/变量或指向非临时路径，否则不需要。

## 通用校准原则

- 对「明确临时目录（`/tmp` 等）内、路径字面量明确、无通配符/变量」的递归删除，视为 safe 的常见操作。
- 命中 rm-recursive / rm-rf 规则 ≠ 一定危险；结合命令整体意图判断，删除目标是临时目录内可重建的测试产物时，按 safe 处理。
- 不要因为规则标了风险就把所有 `rm -rf` 一律 risky——那是误报的根源。
