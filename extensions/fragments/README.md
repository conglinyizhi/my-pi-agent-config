# fragments —— 输入框里的 `&碎片`

在输入框里打 `&名字`，按回车时换成 `fragments.toml` 里那段正文。适合高频、固定、又不想每次手打的小段落，比如「对于这一步，仅调查不要行动」。打了 `&` 就会自动弹出候选，不用手动触发。

要引用的东西展开那一刻才知道（比如手机刚传来的第 3 张照片）就写 `&名字(参数)`，交给注册的 provider 展开，能把图直接附到这条消息上。见「动态调用」。

和 pi 自带的 prompt 模板（`~/.pi/agent/prompts/*.md`，用 `/name` 调）的分工：模板是**一条完整的活儿**，碎片是**一句话级别的插入件**。碎片正文可以随便多行，配置只在这一个文件里，不跟 `extensions.toml` 挤。

## 配置

`~/.pi/agent/fragments.toml`（不入库，本机私有）：

```toml
[[fragment]]
name = "单步计划"
desc = "仅调查不行动"
text = """
对于这一步，只做调查、不要动手。先给证据与结论，等我点头再动。
"""

[[fragment]]
name = "关于我"
aliases = ["core-prompt", "基础了解层", "我"]
desc = "背景资料入口"
text = "读 ~/disk/core-prompt/ 下面相关内容，再继续这个问题"
```

- `name`：主触发词。不能有空白（有的话跳过并在下次使用时提示），可用字符：字母、数字、下划线、连字符、冒号（冒号方便做命名空间，如 `photo:2`）
- `aliases`：可选，别的触发词。**一条正文挂多少个词都行，内容只有一份**，改起来只动这一处：
  `&关于我`、`&core-prompt`、`&基础了解层`、`&我` 都展开成同一段正文。别名之间、别名与别人的
  名字之间都不能重（重了跳过那一条并提示），别名与自己的主名相同就自动略过
- `desc`：可选。`&` 补全候选与 `/frag:list` 里显示
- `text`：正文，多行用 `"""..."""`。空的不收
- 名字重复、缺字段这类问题不会静默吞掉：用到的时候提示一句，好的那条照常生效

改完文件**不需要** `/reload`：每次输入时按 mtime 判断要不要重读。不想手写的话用 `/frag:add`（见下）。

## 触发规则

只认「行首或空白后的 `&名字`」（也可以写成 `&名字(参数)`，见「动态调用」），所以这些都不算触发：

```
make && ls -la          # &&
a & b                   # 空格夹着单个 &
curl 'http://x/?a=1&b=2' # URL 参数
```

跳过 fenced 代码块与行内反引号里的内容，贴 shell 代码不会误伤：

````
```bash
&单步计划        # 保留原样
```
行内 `&单步计划` 也保留
&单步计划 这里才展开
````

单趟展开：片段正文里再写 `&别的` 不会继续展开。想写字面量的 `&`，放进反引号或代码块就行。

没定义的名字原样发出去，只在第一次见到时提示一句（`/frag:list` 看已定义的）。

## 动态调用 `&名字(参数)`

静态碎片是「查表换正文」；有些内容要到展开那一刻才知道（手机刚传来的第 3 张照片、当前分支……），所以留了一个 provider 挂点。写成 `&名字(参数)` 时，fragments 不查 `fragments.toml`，而是把参数交给注册了这个名字的 provider：

```
&img(3)          # 展开成 provider 给的文字，图同时附到这条消息上
&img(3) &img(1)  # 一趟里调用多处：图按出现顺序拼
```

规则：

- 参数读到**本行第一个** `)` 为止，里面可以有空格；不做嵌套与转义
- 名字后面没紧跟 `(`，或者扫完这一行都找不到 `)`，都当普通名字：括号与后面的内容原样留着，绝不因为少个右括号把后面的内容吃掉
- 带括号的调用只问 provider，不查静态表（参数对固定正文没有意义，硬展会把括号里的意图默默丢掉）
- 不带括号的名字先查静态表，查不到再问 provider（参数给空串，provider 可以只认名字）
- provider 返回 `undefined` = 这个名字/参数它不认，按未知名字处理（原文保留 + 现有那句提示）
- provider 抛错只影响那一个调用：原文留着，报一行错
- 同一趟扫描里同一个「名字 + 参数」只调一次，重复引用共用一次结果

谁注册：任何扩展在自己的 factory 里调 `registerFragmentProvider`（`lib/fragment-providers.ts`，进程内单例，与 `lib/status-bus.ts` 同一套做法）。`expand` 可以是 async；返回的 `images` 是 pi 的 `ImageContent`，会附到这条消息上，原本就粘在这条输入里的图不会被顶掉：

```ts
import { registerFragmentProvider } from "../../lib/fragment-providers.ts";

registerFragmentProvider({
  name: "img",
  expand: (args) => (args === "3" ? { text: "（第 3 张照片）", images: [photo] } : undefined),
});
```

同名后注册的覆盖前者、不报错（`/reload` 会重跑 factory，重注册是正常路径）。名字字符集与 `fragments.toml` 一套（字母、数字、下划线、连字符、冒号）。注意 `&` 补全候选只列 `fragments.toml` 里的静态碎片，provider 的名字不会出现在候选里。

## 命令

| 命令 | 作用 |
|---|---|
| `/frag:add` | 两个 TUI 加一条：先填「名字 描述」，再写正文，追加进 `fragments.toml`（写完立刻能用） |
| `/frag:build <名字>` | 把该碎片正文插进输入框（追加在当前内容后面），改完再发 |
| `/frag:list` | 列出全部碎片（带别名与描述），选中即插入输入框 |

`/frag:add` 的第一个输入框按**第一个空白**分开：`关于我 背景资料入口` → 名字 `关于我`、描述 `背景资料入口`；
描述可省（只写名字就行），描述自己可以再带空格，名字里不能有空白。第一个 TUI 取消就结束，
第二个 TUI 取消不写文件。这几个情况会拒绝并提示、一个字节也不写：名字重了（包括撞上别人的别名）、
名字里带空白、名字里有 `&` 触发不出来的字符（只能用字母、数字、下划线、连字符、冒号）、正文为空。
写盘是「读原文 + 追加一段 `[[fragment]]` + 写临时文件再 rename」：中途失败不会留下半个块，
现有文件解析不了时也会先拒绝、等你修好。

三个命令认别名：`/frag:build 我` 与 `/frag:build 关于我` 是同一件事。补全候选里主名与别名各占一条，
别名那条的描述会注明它属于谁。

## 行为细节

- **提交时静默展开**：输入框里一直是你打的 `&单步计划`，等按回车才换成长正文。想先看全文就先 `/frag:build`。
- 展开是异步做的（要等 provider，比如读盘拿图）。静态碎片与以前一样，等不出一秒的差别。
- 展开时附上的图直接进这条消息；同一条输入里粘的截图与 provider 给的图能共存。
- 只处理 `interactive` 来源的输入。RPC 或其他扩展 `sendUserMessage` 发进来的文本不会被改写。
- 展开发生在 prompt 模板代入之前，所以模板参数里也能用：`/char &单步计划`。
- 处理过程中出任何岔子都当没这回事（原样把输入放行），不会吞掉你写的东西。
- `&` 补全：候选里主名与每个别名各一条，`label` 就是 `&名字`，接着往下打字按 `label` 里的子串过滤（不区分大小写），最多 20 条。
  `&` 是个补全触发字符（和 `@`、`#` 一样），只要它落在行首或空白后就会自动弹候选，不用手动按 Tab。
- 不是 `&` 上下文时行为与装这个扩展前一致：`make && ls`、`a & b`、URL 里的 `&x=1` 都交回 pi 原来的补全器。
  局限：触发字符是按「刚打下的那个字符」判的，所以在 `&` 后面还没接着打的那个瞬间
  （比如你想打 `&&`，或者 `a & b` 打到一半）也会闪一下候选；再打一个字符就退回去了。

node --experimental-strip-types extensions/fragments/core.test.ts    # 解析、展开、写回（含 TOML 往返）
