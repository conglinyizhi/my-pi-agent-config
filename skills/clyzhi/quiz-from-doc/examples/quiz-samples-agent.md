# 出题示例二（agent 期实战问卷）

15 道单选题，来自《你管这破玩意叫智能体？》文稿的实战问卷，**原样存档**（含当时洗牌后的选项位置）。
题型标注：
- 概念型：文稿里没有原话，需真正理解才能答对（新标准完整范本）
- 半概念：文稿接近直给，但有理解成分
- 记忆型：文稿原话/直接信息，看一遍就能抄答案（新标准下只参考选项写法，不参考题型）

本批按新标准合格的概念题偏少（5 题），记忆题偏多（8 题）——出题时以本批的选项写法为参考，题型以新标准为准。

读法：带 ✓ 的是正确项，先遮住它自测一遍，再看选项设计好在哪。

## Q1. 视频里给智能体（Agent）下的核心定义是什么？ [✗]

- **A.** 通过提示词优化的问答系统
  - 说明：提示词优化是常见实践
- **B.** 大模型加协助感知外部信息的交互程序 ✓
  - 说明：强调 AI 与外界的交互链路
- **C.** 能自主联网搜索的大模型
  - 说明：联网搜索是 agent 的常见能力
- **D.** 能记住多轮对话的大模型
  - 说明：上下文记忆是对话能力的一部分

## Q2. 视频认为「让 AI 发挥更强大能力」的关键是什么？ [✗]

- **A.** 提升模型参数量
  - 说明：业界常见的提升方向之一
- **B.** 本质上是个沟通问题，不是技术问题 ✓
- **C.** 改进神经网络结构
  - 说明：模型研究的核心议题
- **D.** 增加训练数据量
  - 说明：训练阶段的影响因素

## Q3. 视频里说，人一听就懂的话，程序为什么听不懂？ [△]

- **A.** 程序需要更复杂的指令集才能运行
  - 说明：指令集是处理器支持的指令集合
- **B.** 程序需要更长的上下文才能理解
  - 说明：上下文长度指模型能看到的文本量
- **C.** 程序没有自然语言理解能力，只认约定好的格式 ✓
  - 说明：程序按协议执行
- **D.** 程序缺少足够的训练数据
  - 说明：训练数据是模型学习的素材

## Q4. 视频演示「AI 主动请求补充资料、人来搜索」的例子，本质说明了什么？ [✓]

- **A.** 提示词写得更长，AI 就更聪明
  - 说明：提示词设计影响输出质量
- **B.** 黑盒封装让 AI 具备了与外界交互的能力 ✓
- **C.** 人工搜索比程序搜索更可靠
  - 说明：人工介入是雏形阶段的特征
- **D.** AI 已经具备自主联网搜索的能力
  - 说明：自主联网是 agent 的目标形态

## Q5. ReAct 模式中，Action 和 Observation 分别是什么？ [✗]

- **A.** Action 是调用信息，Observation 是返回结果 ✓
- **B.** Action 是思考过程，Observation 是模型记忆
- **C.** Action 是最终答案，Observation 是用户问题
- **D.** Action 是程序指令，Observation 是程序报错

## Q6. ReAct 模式的循环什么时候结束？ [✗]

- **A.** 程序强制超时
  - 说明：超时机制在工程中常见
- **B.** 调用工具次数达到上限
  - 说明：许多框架会设置调用次数上限
- **C.** 工具调用结果为空
  - 说明：空结果表示没有可用信息
- **D.** 模型觉得信息足够了，返回最终答案 ✓
  - 说明：由模型自主判断

## Q7. 从外部用户的视角看，完整跑完工具循环的 agent 是什么样？ [✓]

- **A.** 每次回答都附带完整日志
  - 说明：日志通常属于调试功能
- **B.** 仍然是一问一答的形式 ✓
- **C.** 用户能看到所有工具调用过程
  - 说明：透明化是部分产品的卖点
- **D.** 用户需要手动确认每一步
  - 说明：手动确认出现在半自动模式

## Q8. ReAct 模式来自哪篇论文，对比了哪些模式？ [✗]

- **A.** 2024 年的 MCP 论文，对比不同协议
  - 说明：MCP 是工具调用协议
- **B.** 2021 年的 GPT-3 论文，对比不同参数量
  - 说明：GPT-3 以规模著称
- **C.** 2023 年的 Transformer 论文，对比编码器与解码器
  - 说明：Transformer 架构是注意力机制的代表作
- **D.** 2022 年的论文，对比原始、CoT 与 ReAct 模式 ✓
  - 说明：ReAct 论文的对比实验设置

## Q9. function calling 技术把什么用 JSON 格式规范了起来？ [✗]

- **A.** 程序的内存管理
  - 说明：内存管理负责资源的分配与回收
- **B.** 模型的训练数据
  - 说明：训练数据决定知识范围
- **C.** 工具调用的自然语言描述 ✓
  - 说明：JSON 是结构化数据格式
- **D.** 用户与模型的日常对话
  - 说明：对话是自然语言交互

## Q10. 视频把提示词拆成 user prompt 和 system prompt，两者分别装什么？ [△]

- **A.** user prompt 是模型回复，system prompt 是工具调用结果
  - 说明：模型回复与工具结果都是对话内容
- **B.** user prompt 是用户提问，system prompt 是角色与流程 ✓
- **C.** user prompt 是工具列表，system prompt 是用户问题
- **D.** user prompt 是答案格式，system prompt 是评分标准
  - 说明：答案格式属于输出约束

## Q11. 视频说函数写死在 agent 主程序里的问题是什么？MCP 怎么解决？ [✓]

- **A.** 函数不安全，MCP 增加沙箱隔离
  - 说明：沙箱是安全机制
- **B.** 函数运行太慢，MCP 用更快的语言重写
  - 说明：性能优化是工程议题
- **C.** 耦合严重且不能复用，MCP 把函数抽成服务并规定通用标准 ✓
  - 说明：服务化与标准化是解耦手段
- **D.** 函数无法联网，MCP 增加网络权限
  - 说明：网络权限是运行环境配置

## Q12. 视频认为 agent 执行复杂任务总是不太靠谱，根本原因是什么？ [✓]

- **A.** 提示词写得不够长
  - 说明：提示词长度与效果的关系
- **B.** 程序执行速度太慢
  - 说明：速度影响使用体验
- **C.** 底层仍是大模型的语言概率模型，无法百分百可控 ✓
  - 说明：概率输出与确定性程序的差异
- **D.** 工具调用次数太少
  - 说明：调用次数是预算问题

## Q13. 视频对当前 agent 技术的总体判断是什么？ [✗]

- **A.** agent 的问题在于算力不足
  - 说明：算力是基础设施问题
- **B.** agent 已经接近完全自动化系统
  - 说明：完全自动化是长期目标
- **C.** agent 不需要大模型也能工作
  - 说明：大模型是 agent 的决策核心
- **D.** 本质是在语言之上硬塞操作能力，离真正自动化还有距离 ✓
  - 说明：对当前技术阶段的评估

## Q14. 用视频的概念看 pi 这类 CLI agent，哪组对应关系正确？ [✓]

- **A.** system prompt 负责角色与规则，工具经 function calling 或 MCP 调用 ✓
  - 说明：function calling 与 MCP 是工具调用的两种实现
- **B.** 人格设定属于 user prompt，用户提问属于 system prompt
- **C.** MCP 工具是模型参数的一部分，随模型一起训练
  - 说明：模型参数在训练阶段确定
- **D.** agent 循环中每轮对话都会重新训练模型权重
  - 说明：权重更新属于训练流程

## Q15. 视频里技术演进的正确顺序是什么？ [✗]

- **A.** 提示词分离 → function calling → MCP ✓
  - 说明：三个阶段层层递进
- **B.** 提示词分离 → MCP → function calling
- **C.** function calling → MCP → 提示词分离
- **D.** MCP → function calling → 提示词分离
