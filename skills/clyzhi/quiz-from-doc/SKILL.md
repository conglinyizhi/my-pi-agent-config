# 文稿出题测验

读一份文稿（字幕/文章/视频文字稿），提炼**可迁移的核心概念**，用 `ask_question` 分批出单选题检验理解。考概念不考复述，不出判断题，不手动安排选项位置——位置交给脚本。

## 触发条件

- 用户给出一份文稿/字幕/文章，要求"总结 + 出题考考我"
- 用户要求"根据这个文档出题 / 测验"
- 用户说"考考我这些概念对不对""我想看看认知对不对"

## 执行

### 1. 读稿列概念

- 用 `read` 读文稿（用户给路径时）
- 拆出**核心概念**（可迁移、可辨析、值得考）与**视频事实**（年份、出处、人名、原话、演进顺序）两类；视频事实是记忆不是理解，原则上不考
- 核心概念优先：能迁移到新场景的、容易被误解的、概念间易混淆的
- 题量不足 10 题时先问用户是否继续，不硬凑，更不用复述题凑数

### 2. 出题

- 每个概念 1 道单选题、4 个选项，先写成 JSON 文件（用 `write` 写临时文件）
- 正确答案标 `is_correct: true`；description 只写中性说明（术语解释、背景补充）

### 3. 洗牌

- 通过 `bash` 跑：`node scripts/shuffle-quiz-options.mjs <json文件>`（相对 SKILL.md 所在目录解析）
- 脚本打乱选项顺序、重分配 A-D，输出 JSON
- 把输出填进 `ask_question`，分批提问（每批 4-5 题，共 ≥10 题）
- 脚本不可用时问用户，不自己手动排位置

### 4. 点评

- 答完一批简短点评；全部答完用文稿里的细节补漏，指出最容易混淆的点
- 收尾给一句整体评价，不展开长篇讲题

## 出题类型

**考概念理解，不考视频复述。文稿是素材不是答案库**——好题在文稿里找不到原话，但理解了概念一定能答对。

优先出：

- **概念迁移**：把概念套到新场景（用户的工具链、反例场景、陌生例子），如「用视频的概念看 pi 这类 CLI agent」
- **反例识别**：哪个选项是对概念的误解/偷换（用户偏好反例理解）
- **易混辨析**：相邻概念的区分（function calling vs MCP、pass@1 vs pass@5、user vs system prompt）
- **因果判断**：为什么 X 导致 Y（如「agent 不靠谱的根源」）
- **假设变体**：「如果……会怎样」的边界情况

避免出（视频阅读理解题）：

- 定义原话复述（「视频怎么说」「定义填空」）
- 纯事实记忆（年份、论文出处、人名、榜单名）
- 演进顺序（除非顺序本身蕴含因果）
- 比喻原文（「像答题时间」这类考的是记忆力不是理解力）
- 一切「文稿里直接搜到答案」的题

## 示例

完整出题案例：

- `examples/quiz-samples.md`：15 道修正后的单选题（benchmark 期），全部为正确案例（含洗牌后选项位置与正确答案标注）
- `examples/quiz-samples-agent.md`：15 道实战问卷原样存档（agent 期），含题型标注（✓概念 / △半概念 / ✗记忆）；✗ 记忆题只参考选项写法，不参考题型

读法：
- 先遮住 ✓ 自测，再对照「说明」看选项设计好在哪
- 干扰项与正确答案等长、等具体、同样可信——只差一个细节/关系
- description 只做中性补充，不给对错线索
- 案例中的答案位置来自脚本洗牌，每次运行结果不同；**不照抄位置**，位置永远交给脚本

## 选项设计

- 干扰项与正确答案**等长、等具体、同样使用专业术语**，只差一个细节/关系
- 好干扰项类型：概念对调、偷换限定条件、张冠李戴、顺序颠倒、以偏概全、手段换成目的
- 每个干扰项单独看都"像真的"——语义分析排不掉
- 出完题站在"不知道这些概念的人"的角度复查每道题（防知识诅咒）

## 避免

- **避免出视频阅读理解题**：答案能从文稿原话/直接信息抄出来的题不考；优先概念迁移、反例识别、易混辨析（详见「出题类型」）
- **避免答案位置有规律**：不连续同位、不整轮同字母；位置只由洗牌脚本决定
- **避免 description 泄漏答案**：不写「这是 X 的方式」（暗示不是）、「X 不是 Y」（明说不是）、「X 才是 Z」（指出谁对）
- **避免长度泄漏**：正确答案不比干扰项长、不比干扰项详细
- **避免离谱干扰项**：「不验证，答了就得分」这类一眼排除的不算选项
- **避免按思考顺序摆放选项**：脑中的"第一答案"不固定放 A
- **避免纯记忆题堆砌**：概念理解为主，纯细节记忆题不超过一半

## 注意事项

- 依赖 Node.js（`node` 命令）；脚本用 ESM（.mjs）
- 脚本校验：每题恰好 4 个选项、恰好 1 个正确答案，违规直接报错退出
- 脚本输入输出均为 JSON（stdin 或文件参数），不修改原文件
- 生成的临时 JSON 用完后清理

## 验证

通过 `bash` 跑：`echo '[]' | node scripts/shuffle-quiz-options.mjs`，应输出「至少 1 题」的错误并退出码 1，而不是崩溃。
