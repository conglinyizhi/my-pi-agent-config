# Git 约定式提交助手

## 触发条件

- 用户说“提交”/“commit”/“帮我提交”/“生成 commit message”
- 用户要求根据当前改动生成 commit
- 当用户主动递出这个 skill 的时候视为用户想要发起提交

## 执行流程

### 1. 准备与检查

确认改动范围：优先暂存区，其次工作区，留意未跟踪的新文件。将待提交内容加入暂存区后，运行技能目录下的 `pre-commit-check.ts`。

最新版本的 Node.js 已经支持直接执行 typescript 文件，避免使用 npm 安装额外的包

- 有错误时停止流程，报告用户并询问是否修复
- 仅有警告时继续，同时告知用户
- 全部通过则进入下一步

### 2. 分析改动

根据差异内容分析：

- **类型**：feat / fix / refactor / chore / docs / style / test / perf / ci / build / revert
- **范围（可选）**：改动涉及的模块短英文名称，如 `sysinfo`、`extensions`、`cli`
- **破坏性**：是否包含破坏性修改（BREAKING CHANGE）

### 3. 生成 commit message

遵循以下模板：

```
<类型>[可选 范围]: <中文描述>

[可选 正文]

[可选 脚注]
```

规则：

- 描述控制在 **30 字以内**，中文
- 范围优先使用修改模块的短英文名称，无法确定时可省略
- 破坏性修改需在类型后加英文感叹号 `!`，如 `feat(api)!: 描述`
- 复杂变动需要正文补充说明；正文与描述重合度过高则不写正文
- 用户补充了额外上下文（user-say）时，将值得说明的内容写入正文
- 正文和脚注末尾**禁止使用句号**
- 仅进行一次提交；若改动不适合一次提交，向用户提问确认

### 4. 发起提交

执行 `git commit` 并附带生成的 message。若 git hook 阻止，停止并简述原因。提交后若工作区仍有修改，文字提示用户。任务完成后简单回复

## 示例

```
feat(sysinfo): 新增 /sysinfo 命令，一键收集系统信息发送给 LLM
```

```
fix: 防止请求竞态

引入请求 ID 与最新请求的引用。忽略非来自最新请求的响应

移除原本用于缓解竞态问题的超时机制，现已不再需要

Refs: #123
```

## 注意事项

- 一次只做一个提交，不合并多个无关改动
- `--no-verify` 仅在 git hook 确实出错且用户明确允许时使用
- 不要在 commit message 中写“根据用户要求”之类的元信息
- 当用户再次递出skill时，多半是其他流程对文件发起了编辑，可以重新跑流程
