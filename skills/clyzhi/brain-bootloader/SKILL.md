# Brain Bootloader — 思维预检

## 定位

轻量级前置检查，不是完整设计流程。在进入 brainstorming / 实现之前，用最短路径确认「我们在解决正确的问题」。

**原则：简单任务直接跳过，不增加无意义复杂度。复杂任务先跑本技能，再过 brainstorming。**

## 触发条件

以下信号出现时启用：

- 用户提出了一个方案/工具/框架，要求你按此执行
- 任务涉及多个变量、不确定性强、失败成本高
- 用户说「帮我做 X，用 Y 方法」
- 感觉方向可能有问题，但说不清哪里不对

**跳过条件**：任务明确、路径清晰、无争议空间的简单操作。

## 五步预检

按顺序执行。每步一句话能说清就一句话，不展开。

### 1. 目标重定义

用户的「做法」不等于「目标」。先问：TA 最终想达到什么结果？剥离手段，还原目的。

```
用户说：帮我用 React 重写这个页面
真实目标可能是：页面性能有问题 / 维护成本高 / 想加新功能但旧代码改不动
```

### 2. 隐藏假设扫描

快速识别用户要求中未经验证的前提：

- 这个工具/方案一定是最合适的吗？
- 有没有「大家都这么做」所以默认正确的路径？
- 有没有因为不知道替代品而选择当前方案的可能？

### 3. 信息差补充

主动提供用户可能不知道但会影响决策的信息：新工具、新范式、行业做法变化。涉及可能变化的信息时先核实。

### 4. 替代方案速览

至少考虑三类：

| 类型 | 问题 |
|------|------|
| 更简单 | 有没有 20% 复杂度实现 80% 效果的方法？ |
| 更稳 | 有没有更成熟、更少踩坑的方案？ |
| 更优 | 有没有上限更高的路线？ |

不必凑数。原方案确实最好就保留，但要说明依据。

### 5. 对抗性复核

最后从反方视角问一句：如果这个方案会失败，最可能死在哪里？有没有致命盲区？

## 追问规则

预检中发现模糊决策时，**不要直接输出结论**。进入追问：

- 事实性问题先自己查代码/环境，不问用户
- 决策性问题给出 **2-3 个选项**，每个附上反例（选这个最可能栽在哪里），让用户选
- 每次只问一个问题，等用户回答后再继续
- 追问的靶心始终是：「你真的想清楚该不该做这个了吗？」

不需要穷尽所有分支——只在方向性问题上追，细节留给 brainstorming。追问结束后再输出结论。

**跳过追问**：5 步预检全部清晰、无争议空间时，直接输出结论。

## 输出格式

预检完成（且追问结束）后，给出简洁结论：

```
方向判断：✅ 原方案可行 / ⚠️ 需要调整 / ❌ 建议换方案
建议路线：[一句话]
关键风险：[如有]
下一步：进入 brainstorming / 直接执行
```

## 与 brainstorming 的关系

```
brain-bootloader          brainstorming            writing-plans
    (方向预检)      →       (方案设计)       →        (实现计划)
```

- bootloader 回答：「我们该不该做这个？」
- brainstorming 回答：「我们该怎么做？」
- bootloader 产出一个方向判断；brainstorming 产出设计文档和规格书。

串联规则：复杂/模糊/高风险任务先跑 bootloader，确认方向后显式调用 brainstorming。简单任务直接走 brainstorming。
